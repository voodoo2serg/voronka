# Воронка

Система управления маркетинговыми воронками и публикациями в мессенджерах на собственном сервере. Вход в административную панель — через личный Telegram-аккаунт. Владелец и помощница работают под разными аккаунтами и получают отдельные права.

**Статус: исходный MVP для тестового развёртывания.** Код добавлен через GitHub API при недоступной локальной среде исполнения. Результат тестов определяется GitHub Actions; до зелёного CI и проверки с настоящими ботами этот пакет не следует считать готовой производственной системой.

## Что реализовано в исходниках

- FastAPI, PostgreSQL, Redis, Docker Compose, Caddy HTTPS.
- Вход из Telegram Mini App: проверка подписи initData, свежести, одноразового обмена и активной роли на каждом запросе. Bearer-сессия — в памяти страницы; серверная сессия — в Redis.
- Роли owner/editor/manager/viewer; доступ по подключению.
- Несколько Telegram-ботов, MAX-ботов и VK-сообществ; секреты только в окружении.
- Граф: текст, фото, видео, голос, документ, вопрос, опрос, условие, ожидание, выдача продукта, CRM-этап, задача, завершение.
- Черновик с защитой от конкурентных изменений; неизменяемая опубликованная версия; участники продолжают свою версию.
- Блокировка выдачи продукта до выполнения условий, последовательный опрос, остановка /stop.
- Webhook-события сохраняются в PostgreSQL с защитой от повторной доставки.
- Outbox отправок и таймеры в PostgreSQL переживают перезапуск.
- Контакты, идентификаторы, задачи, журнал, ручные ответы менеджера.
- Публикация текста в выбранные Telegram-каналы и группы при необходимых правах бота.
- Панель с формами и JSON-редактором, контакты, задачи, журнал и ошибки доставки.
- Ручной ответ менеджера приостанавливает сценарий и отменяет ещё не отправленные автоматические сообщения.

## Границы первой версии

Воронки пока редактируются JSON-формой; перетаскивание блоков отсутствует. Входящие ответы — личные текстовые сообщения, без callback-кнопок и аудиораспознавания.

Telegram отправляет медиа по HTTPS URL. MAX и VK используют резервный вариант — текст со ссылкой на медиа. Нативные загрузки/кружки и публикации на публичные площадки MAX/VK не реализованы. WhatsApp отсутствует. Групповые ключевые слова, аналитика целей, тех-чат, медиабанк, календарь публикаций, платежи и возобновление paused-сценария после менеджера — следующие этапы: [план](docs/ROADMAP.md).

В этой версии требуется **один worker**. Перед увеличением числа процессов нужна сериализация по identity. Циклы графа отклоняются. Выполнение шага означает отправку/ответ, а не доказанный просмотр видео.

Публичный URL бонуса ограничивает момент отправки, но не доступ по известной ссылке. Для приватного курса потребуется объектное хранилище с короткими подписанными ссылками и проверкой entitlements.

## Сервер

Рекомендуемая стартовая конфигурация: 4 vCPU, 8 ГБ RAM, 80–160 ГБ SSD, Ubuntu 24.04 LTS, Docker Engine + Compose plugin. Для небольшого теста: 2 vCPU / 4 ГБ. Это инженерная оценка, не нагрузочный замер. Имеющийся сервер с 16 ГБ RAM подходит при достаточном свободном ресурсе; Ollama и перекодирование видео конкурируют за CPU/RAM.

Нужны домен с DNS на сервер, входящие TCP 80/443, SSH для обслуживания, исходящий HTTPS к платформам и реестрам образов. PostgreSQL/Redis/API не публикуют наружу порты.

## Запуск

1. `git clone https://github.com/voodoo2serg/voronka.git`
2. `cd voronka`
3. `cp .env.example .env`
4. В .env задайте DOMAIN, пароль PostgreSQL (одинаковый в POSTGRES_PASSWORD и DATABASE_URL), OWNER_TELEGRAM_ID и ADMIN_BOT_TOKEN. Токены в GitHub не помещать.
5. Создайте через BotFather отдельного административного бота и пользовательского бота. Первый открывает панель, второй ведёт воронки и публикует.
6. `docker compose up -d --build`
7. `docker compose exec api python -m scripts.register admin`
8. Откройте чат административного бота и меню «Воронки». Вход доступен разрешённому Telegram ID.
9. В панели добавьте Telegram-подключение: TG_MAIN_TOKEN, TG_MAIN_WEBHOOK_SECRET, config с username без @.
10. Заполните эти переменные в .env: токен пользовательского бота и случайный секрет. `docker compose up -d --force-recreate api worker`
11. `docker compose exec api python -m scripts.register CONNECTION_ID`
12. Создайте воронку из [примера](examples/mini_course.json). Замените example.org URL настоящими файлами. Выберите ID подключения и опубликуйте.
13. Создайте точку входа и пройдите полученную Telegram-ссылку с другого аккаунта.
14. Добавьте помощницу: её числовой Telegram ID, editor, доступные connection_ids. Общий пароль или общий Telegram-аккаунт не нужен.

MAX: подключение max, переменные MAX_MAIN_TOKEN / MAX_MAIN_WEBHOOK_SECRET, регистрация webhook той же командой. Trust store должен доверять цепочке MAX API; TLS-проверку отключать нельзя. При необходимости установите официальный дополнительный корневой сертификат в trust store и HTTP-клиент, затем проверьте соединение.

VK: подключение vk, config с group_id и confirmation_env, переменные VK_MAIN_TOKEN / VK_MAIN_WEBHOOK_SECRET / VK_MAIN_CONFIRMATION; в сообществе настройте Callback API и message_new.

Для MAX/VK ссылка входа должна передавать возвращённый payload как bot_started.payload / message.ref. Готовые ссылки MAX/VK панель пока не формирует.

## Проверка и эксплуатация

`python -m pytest -q`

GitHub Actions проверяет компиляцию Python, тесты, Compose-конфигурацию и миграцию PostgreSQL: upgrade → downgrade → upgrade. Нужны также проверки настоящих webhook, media API, прав бота и сертификатов.

sent означает успешный ответ платформы, а не чтение пользователем. При сетевом тайм-ауте — unknown: автоматический повтор выключен. Перед ручным повтором проверьте мессенджер.

Публикация в несколько площадок не атомарна: результат фиксируется для каждой. Секреты не выдаются помощнице и не возвращаются API. Резервная копия: `sh scripts/backup.sh`; хранить отдельную зашифрованную копию вне сервера и проверять восстановление. Сессии — Redis; события, очередь и таймеры — PostgreSQL. Автоматического объединения людей по имени/телефону нет.
