# Воронка

Система воронок на собственном сервере: видео и кружки → вопросы → опрос → PDF → предложение → задача менеджеру. Административная панель открывается в Telegram. Вы и помощница входите своими аккаунтами; права проверяются на сервере.

**Рабочая реализация для запуска Telegram-воронок.** Серверный цикл, PostgreSQL, миграции, MP4 и Docker проверяются автоматически. Реальные токены, права бота, домен и доставку в ваш аккаунт нужно проверить после установки. MAX/VK пока имеют более узкую поддержку медиа; WhatsApp отсутствует.

## Что можно делать без программирования

- Создавать воронки из шаблонов: пять видео и книга, лид-магнит, кастдев.
- Добавлять и редактировать шаги обычными полями: текст, материал, варианты ответа, следующий шаг, условие, задержка, опрос, доступ, задача.
- Загружать материалы в медиабанк или отправлять/пересылать их пользовательскому Telegram-боту с разрешённого административного аккаунта.
- Выбирать видео, кружок, голосовое, фото или PDF; предварительно проверять отправку себе.
- Публиковать версии и получать ссылки входа с источником/кампанией.
- Вести несколько ботов и публиковать текст в выбранные собственные Telegram-каналы.
- Смотреть контакты, ответы, задачи, состояния участников и ошибки доставки.
- Приостанавливать, продолжать и останавливать сценарий; отвечать вручную.
- Назначать помощнице роль editor и доступ к отдельным подключениям.

Редактор использует список шагов и поля переходов, без drag-and-drop. JSON оставлен как дополнительный режим импорта/экспорта. Циклы графа запрещены. Опубликованные участники продолжают свою неизменяемую версию.

## Сервер

Рекомендуемый старт: 4 vCPU, 8 ГБ RAM, SSD 80–160 ГБ, Ubuntu 24.04 LTS, Docker Engine + Compose plugin. Это инженерная оценка, не нагрузочный результат. Имеющийся сервер с 16 ГБ RAM подходит при свободном ресурсе. Нужны домен, DNS на сервер, входящие 80/443 и исходящий HTTPS.

В Compose: Caddy HTTPS, FastAPI, PostgreSQL 16, Redis 7, один worker, Alembic и постоянный volume media. FFmpeg включён в образ для проверки формата загрузок. PostgreSQL/Redis не открыты наружу. MinIO и Celery для этой версии не нужны.

## Установка

1. `git clone https://github.com/voodoo2serg/voronka.git`
2. `cd voronka`
3. `cp .env.example .env`
4. Заполните DOMAIN, OWNER_TELEGRAM_ID, ADMIN_BOT_TOKEN, TG_MAIN_TOKEN, TG_MAIN_WEBHOOK_SECRET. Укажите одинаковый пароль PostgreSQL в POSTGRES_PASSWORD и DATABASE_URL. Токены не коммитить.
5. Через BotFather создайте два бота: административный для панели и пользовательский для материалов/воронок.
6. `docker compose up -d --build`
7. `docker compose exec api python -m scripts.register admin`
8. Откройте административного бота и меню «Воронки». В разделе «Настройки» добавьте Telegram-подключение с именами переменных TG_MAIN_TOKEN / TG_MAIN_WEBHOOK_SECRET.
9. Нажмите «Проверить и подключить webhook». Система получит username бота и зарегистрирует события сообщений и кнопок.
10. В «Настройках» добавьте помощницу: её числовой Telegram ID, editor, выбранные подключения.
11. В «Медиабанке» загрузите видео и PDF или отправьте их пользовательскому боту со своего аккаунта. Если медиа отправляет помощница, сначала выдайте ей доступ к этому подключению.
12. Для проверки отправки откройте пользовательского бота и нажмите Start. В панели выберите материал, этого бота и свой Telegram ID → «Отправить материал мне».
13. Создайте воронку, примените шаблон «Мини-курс: пять видео → опрос → книга», выберите материалы для всех пяти уроков и книги, заполните тексты и опрос.
14. Сохраните, опубликуйте и создайте ссылку входа. Пройдите её другим аккаунтом целиком.

После этого основная работа идёт в панели: материалы, тексты, шаги, ссылки, контакты. Изменение токенов остаётся серверной операцией; после изменения .env пересоздайте api и worker.

## Видео и другие материалы

Загрузка через панель: MP4/H.264, фото JPEG/PNG, голос OGG/Opus, MP3 или M4A/AAC, PDF. Видео-кружок: квадратное MP4 до 60 секунд. Фото до 10 МБ, прочие файлы до 50 МБ. Автоматического перекодирования нет: неподходящий файл сразу отклоняется с объяснением.

Большое готовое видео можно отправить или переслать пользовательскому Telegram-боту: медиабанк сохранит его file_id. Он привязан к конкретному боту. Для загруженных на сервер материалов worker получает и сохраняет собственный file_id при первой отправке; дальше файл повторно не загружается. Материал с единственным Telegram file_id нельзя назначить другому боту без подготовки.

Локальные файлы лежат в закрытом Docker volume и не имеют публичной ссылки. Административный предпросмотр требует авторизации. PDF отправляется участнику после выполнения заданных условий. Уже выданный PDF нельзя отозвать из устройства пользователя.

«Продолжить» означает подтверждение участника, а не доказанный просмотр видео. Для проверки знаний можно поставить вопрос с вариантами и условие по ответу.

## Другие мессенджеры

| Возможность | Telegram | MAX | VK |
|---|---|---|---|
| Личная воронка и опрос | Да | Да, требуется проверка аккаунта | Да, требуется проверка сообщества |
| Нативные видео/кружки/голос/PDF | Медиабанк и file_id | Пока резервная HTTPS ссылка | Пока резервная HTTPS ссылка |
| Кнопки ответа | Callback с защитой от старой кнопки | Callback | Текстовые кнопки с payload |
| Публикации в свои площадки | Текст в каналы/группы | Следующий этап | Следующий этап |
| Ссылка входа в панели | Формируется | Payload, ссылка вручную | Ref, ссылка вручную |

При назначении локального материала MAX/VK публикация требует резервный HTTPS URL: отсутствующая возможность не маскируется. Вход в админку через Telegram не предоставляет права каналов — пользовательского бота нужно отдельно добавить администратором в свои Telegram-каналы.

## Надёжность

- Inbox сохраняет события до ответа webhook и исключает повтор по external_event_id.
- Ранний ответ ждёт отправки вопроса в БД, а не теряется.
- Кнопка связана с текущим вопросом случайным nonce; старая кнопка не отвечает на следующий вопрос.
- Сообщения одного run отправляются в порядке очереди; ошибка первого блокирует последующие.
- Задержка начинается после предшествующих отправок и переживает перезапуск.
- Явный ответ 429 повторяется по retry_after, не более восьми попыток. Неизвестный сетевой результат автоматически не повторяется.
- Пауза удерживает сообщения, продолжение возвращает их в очередь; ручной ответ ставит сценарий на паузу.
- PostgreSQL advisory lock запрещает случайный запуск второго worker.
- Доступ отозванного администратора блокируется и в уже выданной сессии.
- Зависимости Python зафиксированы в constraints.txt.

sent означает успешный ответ платформы, а не прочтение. Массовые рассылки, платежи, групповые ключевые слова, полная BI и несколько worker — отдельные следующие задачи.

## Проверки

`python -m pytest -q`

Браузерные проверки: `pip install -r requirements-dev.txt`, `python -m playwright install chromium`, `RUN_BROWSER=1 python -m pytest -q tests/test_editor_browser.py`.

CI проверяет серверные тесты, полный HTTP-сценарий на PostgreSQL, миграции upgrade/downgrade, Docker-сборку, доступность FFprobe и запись в media volume. Отдельная браузерная проверка собирает мини-курс на большом и мобильном экране. Ответы платформ в автоматических проверках имитируются; реальная доставка проверяется при установке.

## Обслуживание

В панели: «Настройки → Готовность сервера» и «Доставка». Резервная копия: `sh scripts/backup.sh` сохраняет БД и media volume. Храните обе копии вне сервера и проверяйте восстановление.
