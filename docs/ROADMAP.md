# План доведения до рабочего продукта

## Этап 1 — проверка baseline

Цель: подтвердить серверный цикл Telegram от входа до выдачи PDF и задачи менеджеру. Установить сервер, подключить тестовый канал, владельца и помощницу. Пройти GitHub Actions и ручные проверки из OPERATIONS. Дополнить имеющиеся mock-тесты адаптеров реальными обезличенными fixture webhook и ошибками сети. Зафиксировать версии зависимостей после успешного CI.

Приёмка: вход постороннего запрещён, scope работает, повтор событий безопасен, опрос не обходится, таймер переживает перезапуск, ошибки доставки видны.

## Этап 2 — удобство работы помощницы

- Редактор блоков с полями текста, медиа, переходов и условий; импорт/экспорт JSON сохранить.
- Шаблоны: лид-магнит, мини-курс, кастдев, вебинар, продажа курса.
- Раздел площадок с проверкой прав бота; роли на конкретную площадку.
- Карточка контакта, задачи с исполнителем и сроком, теги, поиск, CSV.
- Возобновление воронки после менеджера с явным выбором состояния.
- Публикация черновик → согласование → расписание → результат для каждой площадки.

Приёмка: помощница собирает воронку из шаблона без редактирования JSON; публикации и ошибки видны на одной странице.

## Этап 3 — медиа и другие площадки

- Assets и asset_variants с принадлежностью к подключению; S3/MinIO и подписанные URL.
- Telegram upload/file_id с учётом токена бота, video_note и voice.
- MAX upload/token/attachment; реальные интеграционные тесты.
- VK загрузки/attachment и отдельные операции публикации на стене.
- Capability-матрица: «нативно», «замена», «недоступно» видна до публикации.
- Ссылки входа MAX/VK, проверенные на действительных ботах.
- Настраиваемые адаптеры нескольких ботов каждой платформы.

Приёмка: один материал доставляется выбранным площадкам в ожидаемом формате, ошибка одной площадки не ломает остальные.

## Этап 4 — маркетинговая автоматизация

- Групповые источники/ключевые слова, правила matching, cooldown 600 секунд, журнал конверсии в личку.
- Игнорирование собственных событий, ботов и выбранных администраторов в рамках доступного платформой API.
- Goals и аналитика по событиям вход/ответ/опрос/выдача/заявка.
- Attribution touchpoints без перезаписи первого источника.
- Настраиваемые score и automation_rules с валидируемым языком условий, без выполнения Python/eval.
- Tech notifications через отдельный outbox.
- Follow-up 120 секунд по шаблону: одно напоминание, затем завершение.
- Согласие/отказ от последующих маркетинговых сообщений и исключение отказавшихся.

Приёмка: доказуемая воронка по источникам; события чтения/просмотра не выдумываются.

## Этап 5 — надёжность и масштабирование

- Пер-соединение rate limit, контролируемый backoff, dead-letter и replay.
- Сериализация переходов по identity; несколько worker без гонок и повторных задач.
- Тесты аварии до/после отправки, out-of-order и concurrent webhook.
- Метрики очереди, worker heartbeat, оповещения о подписках MAX и webhook-ошибках.
- Backup/restore упражнения, аудит зависимостей и секретов.
- Полный catalog products/entitlements; проверка прав на скачивание.

## Дополнительные интеграции

WhatsApp Cloud API: только официальный business-account, поддерживаемые шаблоны и окно сообщений. Платежи — отдельный webhook с подписью и дедупликацией. Слияние контактов — только после подтверждения пользователем, с журналом и отменой. Видеоплеер — отдельный модуль телеметрии; кнопка «Продолжить» не считается просмотром.
