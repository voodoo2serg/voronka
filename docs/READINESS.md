# Аудит готовности к запуску

## Оценка исходной версии

Первая версия была техническим MVP, а не готовым рабочим инструментом: ввод сценариев требовал JSON, медиабанк отсутствовал, ранний ответ мог пропасть, задержки отсчитывались до отправки контента, ошибки не блокировали последующие сообщения, паузу менеджера нельзя было снять. Зелёные первоначальные unit-тесты не покрывали эти случаи.

## Исправления

- Редактор шагов с обычными полями и шаблонами; JSON только дополнительный режим.
- Закрытый медиабанк, загрузка и импорт из Telegram, проверка MP4, file_id отдельно для каждого бота, тестовая отправка себе.
- Долговечное ожидание раннего ответа, nonce текущего вопроса, защита от старых кнопок.
- Очерёдность отправки, блокировка за failed/unknown, явный retry_after, задержка после отправки, heartbeat и блокировка второго worker.
- Пауза с удержанием сообщений, возобновление и остановка из панели.
- Полный HTTP-сценарий и проверки на PostgreSQL; отдельный тест интерфейса на широком и мобильном экране.
- Регистрация webhook из панели, preflight и резервная копия БД с медиа.

## Доказательства и границы

Серверные проверки охватывают цикл видео → ответ → опрос → PDF → цель → задача, повтор webhook, отзыв прав, ранний ответ, старую кнопку, паузу/продолжение, задержку, 429, реальные MP4-файлы и сохранение версии. Docker проверяет образ, FFprobe и запись в media volume.

В автоматических проверках ответы мессенджеров имитируются. Они не доказывают действительность ваших токенов, права вашего бота в канале, доступность домена или доставку настоящему аккаунту. Эти проверки выполняются один раз после установки через preflight, активацию webhook и тестовую отправку.

Готовый рабочий сценарий этого релиза — Telegram. MAX/VK имеют ядро личных сценариев и резервные ссылки для медиа; их нельзя объявлять полностью равными Telegram. WhatsApp, платежи, групповые триггеры, массовые рассылки и несколько worker не реализованы.

## Приёмка после установки

1. Владелец и помощница входят своими аккаунтами; посторонний аккаунт не входит.
2. Preflight подтверждает БД, Redis, media volume и worker.
3. Тестовое видео и PDF приходят через выбранного бота.
4. Мини-курс из пяти уроков проходит другой аккаунт; книга приходит после опроса.
5. Ручное сообщение приостанавливает сценарий, resume его продолжает.
6. Перезапуск контейнеров сохраняет прогресс и отложенные действия.
7. Проверено восстановление базы и файлов из резервной копии.
