# Эксплуатация сервера

## Компоненты

| Компонент | Сейчас | Назначение |
|---|---|---|
| Ubuntu 24.04 LTS | Требуется на сервере | ОС |
| Docker Engine и Compose plugin | Требуются | Запуск контейнеров |
| Caddy | В Compose | HTTPS, прокси |
| FastAPI | В Compose | API, Mini App, webhook |
| PostgreSQL 16 | В Compose | Контакты, сценарии, очереди, таймеры |
| Redis 7 | В Compose | Административные сессии |
| Python worker | В Compose | Движок и доставка |
| Alembic | Одноразовый migrate | Миграция перед запуском |
| MinIO или внешнее S3 | Следующий этап | Медиабанк и закрытый контент |
| FFmpeg | Следующий этап | Подготовка вариантов медиа |
| Celery | При масштабировании | Опциональный диспетчер фоновых работ |

На первом сервере дополнительных LLM, Qdrant, LangGraph и Kubernetes не требуется. Система может работать рядом с RAGA, но должна иметь отдельную БД, каталоги, бот-токены и порт/домен.

## Доступ

Внешние порты: 80/443 и ограниченный SSH. PostgreSQL/Redis/API — только сеть Compose. Firewall сервера должен разрешать административный SSH только выбранным адресам либо через установленный безопасный канал доступа.

Файл .env не коммитить, права файла ограничить владельцем сервера. После изменения окружения пересоздать API и worker. Помощница вводит содержание в панели, токены ей не требуются. Назначение прав не означает предоставление SSH.

Административный бот не имеет webhook-обработчика бизнес-сценариев: он открывает Mini App через меню. Его токен используется только для проверки Telegram-входа и настройки меню. Пользовательские боты имеют свои webhook и токены.

## Проверки после запуска

1. GitHub Actions должен пройти тесты и миграции.
2. HTTPS домен открывается без ошибки сертификата.
3. /health отвечает ok, PostgreSQL и Redis доступны.
4. Основной владелец входит; посторонний Telegram ID получает отказ.
5. Помощница видит только выделенные подключения; попытка API-запроса к чужому connection_id получает 403.
6. Бот отправляет тестовый пост в разрешённый тестовый канал.
7. Ссылка приводит в правильную воронку; source записан в journal.
8. Повторный webhook не создаёт второй запуск.
9. PDF не отправляется до завершения всех вопросов.
10. Перезапуск worker не теряет ожидание.
11. /stop останавливает текущую воронку.
12. Ручной ответ менеджера приостанавливает автоматизацию.
13. Доставка с неизвестным результатом требует ручной проверки.
14. Проверить восстановление БД из копии на отдельном тестовом экземпляре.

## Обновление

Перед обновлением сделать копию БД и сохранить текущий commit. Проверить миграции на копии; затем обновлять код и запускать Compose. В baseline изменение schema требует новой Alembic revision; замороженную schema_v1 не менять. Не запускать downgrade на рабочей БД: он удаляет данные.

Команды:
- docker compose ps
- docker compose logs --tail=100 worker
- docker compose logs --tail=100 api
- sh scripts/backup.sh

Приложение намеренно не печатает URL запросов с бот-токенами. Не включать подробное HTTP-логирование библиотек без маскирования credentials. Тексты ответов в БД доступны уполномоченным администраторам.

## Резервные копии

Ежедневный pg_dump, копия вне сервера, шифрование и отдельный ключ восстановления. Рекомендуемая политика: 7 дневных, 4 недельных, 3 месячных; это предлагаемые параметры, а не настроенная автоматизация.

Redis можно восстановить без бизнес-данных: пользователи повторно войдут в админку. PostgreSQL терять нельзя. Пока медиа внешние — хранить исходники отдельно. После добавления S3 резервировать и объектное хранилище.

## Ограничения эксплуатации baseline

Один worker. Нет массовых рассылок по контактам, автоматических ретраев, полноценного health-monitor worker, сканирования загрузок, платёжного обработчика и приватного медиахранилища. Административный вход работает через Mini App; отдельный вход в обычном браузере не реализован. Принудительное завершение всех активных запусков через UI пока отсутствует.

Перед производственным использованием нужны нагрузочная проверка, мониторинг возраста очереди/ошибок webhook и ротация секретов. Для MAX отдельно проверить trust store и успешность настоящего HTTPS-соединения. Не обходить ошибки сертификата через verify=False.
